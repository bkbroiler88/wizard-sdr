Signalhound CYD — a 2.4 GHz watcher that keeps its own evidence

A standalone 2.4 GHz spectrum watcher built on the Cheap Yellow Display and the ESP-SDR debug-path receiver. Core-0 owns the radio and runs a lightweight live classifier; Core-1 owns the touchscreen, the SD card, and the deferred decoder. The two never block each other — capture never waits on UI, decode never steals the radio.

Core-0 · RF Core-1 · UI + decode

Dual-core architecture

A hard split with a lock-free ring between them. Core-0 produces samples at line rate; Core-1 is a consumer with three distinct hats: UI compositor, SD writer, and decoder worker. The decoder only runs when the operator asks or when the mask trigger fires.

Feature list

Grouped by job. Each line notes the core doing the work.

▸ RF capture

  • C0 Live spectrum trace at ~60 FFT/s, 256–1024 bin
  • C0 Scrolling waterfall, 24 rows on-screen, 120 in memory
  • C0 1 MHz tuning FREQ 2412..2482
  • C0 Bandwidth BANDWIDTH 4, 8, 10, 20 MHz
  • C0 Hardware AGC or manual gain index
  • C0 Peak hold, averaging ×2 ×4 ×8, min-hold
  • C0 Burst-to-SRAM capture: 10 ms @ 20 MS/s, 400 KB

▸ Classification (live)

  • C0 OFDM-vs-FHSS-vs-CW shape detector per burst
  • C0 Channel-energy pie across WiFi 1 / 6 / 11
  • C0 BLE adv channel energy (37 / 38 / 39)
  • C0 Jammer / interferer flag (floor rise > threshold)
  • C0 Microwave oven signature (duty-cycled 2.45)
  • C0 Unknown-emitter badge for anything unclassified

▸ Triggers

  • C0 Mask trigger — bin breach promotes burst with pre-trigger
  • C0 RSSI threshold trigger with hysteresis
  • C0 Timer trigger — every N seconds, auto-capture
  • C0 Shape trigger — "any FHSS pattern" or "any OFDM burst"
  • C0 Pre-trigger buffer: last 2 ms kept in ring

▸ Storage

  • C1 Burst files /caps/YYYYMMDD-HHMMSS.iq
  • C1 Session log /sessions/*.jsonl (events, classifier output)
  • C1 Decoded findings /findings/*.jsonl
  • C1 Decimated spectrum log (1–30 days of trend data)
  • C1 Baseline file for "known good" emitters
  • C1 Export tab: WAV / SigMF / CSV

▸ Deferred decoders

  • C1 NRF24 1M / 2M GFSK (fast)
  • C1 BLE 1M / 2M GFSK (fast)
  • C1 802.15.4 O-QPSK (Zigbee / Thread / Matter frames)
  • C1 LoRa 2.4 CSS, SF7–SF10
  • C1 WiFi 802.11b DSSS (short frames)
  • C1 WiFi 802.11g/n OFDM (slow — 5-10× capture time)
  • C1 One decoder in RAM at a time; bank selectable in Settings

▸ Operator UX

  • C1 Nine screens, resistive-touch friendly big targets
  • C1 Dirty-rect redraw only (per the no-flicker rule)
  • C1 Findings log scrollable on-device
  • C1 Tap a bar in LIVE to jump-tune to that bin
  • C1 One-tap REC = mark the moment, 10ms burst to SD
  • C1 Progress badges on CAPTURES rows (◐ ✓ ◇)
  • C1 Settings persist to NVS, decoder bank persists to SD

Core allocation invariants

The rules the scheduler enforces so capture never waits on UI and decode never steals the radio.

While the screen shows Core-0 is doing Core-1 is doing
HOME radio idle, standby UI + decode if queued
LIVE SPECTRUM capture, FFT, classify redraw, touch, (no decode — would fight RAM)
TRIGGER (armed) capture, FFT, mask check UI, SD write only when fired
CAPTURING (burst phase) fill SRAM at line rate UI frozen until burst done
CAPTURING (SD-drain phase) radio free, light live trace OK SRAM → SD at SD speed
CAPTURES browser radio idle UI + decode if queued
DECODING radio free, light live trace OK decoder + progress UI
FINDING DETAIL radio idle UI + decode if queued
TUNE retune, hold FFT UI
SETTINGS radio idle UI + decode if queued
